# Task1：SCL 离线分析、校验与浏览工作台

P0 至 P6 已通过。完整 XSD 校验作为 P7 单列。日期为 2026-11-06。验收记录见 [P0](Task1P0.md)、[P1](Task1P1.md)、[P2](Task1P2.md)、[P3](Task1P3.md)、[P4](Task1P4.md)、[P5](Task1P5.md) 和 [P6](Task1P6.md)。规则目录见 [SclRules.md](SclRules.md)。

## 1. 产品结论与需求澄清

需求足以进入设计和分阶段开发。建议把下一阶段产品定义为“可追溯的 SCL 离线分析工作台”：用户打开文件，了解设备及通信配置，查找数据集和报告，沿引用找到数据对象，查看校验问题，并回到原文确认依据。

这比直接增加一个 XML 树更符合电气工程人员的使用方式。核心体验应是“找到信息 → 理解关系 → 查看依据”，后续仿真复用同一领域模型。

需要明确的边界：

| 原始表达或现有约定 | 判断与处理建议 |
|---|---|
| 当前 AGENTS 要求首期不解析 SCL | 首期骨架已存在；本任务是其后的扩展阶段。先核验已有阶段门槛，再逐阶段接入；本提案本身不表示解析已完成 |
| 打开 CID、SCD 等 | 本期保持 ICD/SCD/CID/CCD 的现有入口，扩展名不区分大小写；内容按 XML 根元素和命名空间识别。CCD 不预设为与标准 SCD 完全等价的格式，按供应商方言识别，无法识别时仅提供诊断/原文；SSD/SED/IID 留待后续明确 |
| 校验“有无内容缺失” | 拆成 XML、结构、引用和工程检查；只能发现规则覆盖的缺失，不能证明文件完全正确，也不能凭单份文件知道现场是否少了一台设备 |
| MMS 报文 ID | 含义不唯一。默认提供 MMS 对象标识映射；运行时请求/响应的 Invoke ID 不存在于静态 SCL 中。GOOSE/SV 的 APPID 也不能当作 MMS 报文 ID |
| MMS 报告 ID | 展示 ReportControl 的原始 rptID，同时独立展示报告控制块引用、数据集引用及可推导信息；它们不是同一字段 |
| Qt 与网页美化/动效参考 | 保留 Widgets + ADS，通过配色、排版、图标、反馈提升观感；不为视觉效果迁移 Web 技术栈或立即引入 QML/MDI |
| 现有说明提到后台独立进程和 Redis | 本期离线分析采用 UI 进程中的后台任务，经应用服务隔离；不依赖 Redis。双进程协议服务仍是后续架构方向 |

默认采用：单文件活动会话、只读分析、中文界面配英文术语、Windows MinGW64 优先验证、离线可用。多文件比较、编辑保存、自动修复、设备通信、抓包、订阅和仿真实例生成均不进入本期。

用户无需先了解全部 SCL 知识。唯一会改变数据范围的术语问题是“报文 ID”是否指向厂家专用字段；在获得字段示例前，按上述默认含义设计，不编造字段。

## 2. 已检查的项目和真实样本

### 2.1 项目现状

- `src/gui/MainWindow.*` 已有 ADS 主窗、两类实体列表、详情占位 Dock 和文件选择入口。当前只判断扩展名，不读取 SCL 内容；文件过滤器仍包含“所有文件”，提交时再拒绝不支持的后缀。
- Redis 检查与日志位于 `src/core/`，已使用后台 PING；离线分析不需修改其生命周期。
- 根 CMake 使用 C++17、Qt Core/Widgets/Concurrent 等、QtADS 5.0.0 和静态 hiredis 1.3.0。Qt Core 的流式 XML 读取能力可先满足解析原型，无需立即增加 XML 库。
- `docs/DEVELOPMENT.md` 前半部分存在长期 QML/MDI、双进程设想，后半部分记录当前 Widgets 骨架；实施时必须区分未来规划与当前实现。
- 设计阶段仅做代码阅读和只读统计；后续 P0 已重新完成 Debug 配置/构建及五组测试，并按 namespace URI 复核真实样本，证据和限制见 [Task1P0.md](Task1P0.md)。

### 2.2 样本事实

原 P0 本地文件：`E:/Document/项目/自动配置/湖北武汉220kV电校培训变20261021.scd`。P1 在新电脑使用 `D:/3Document/湖北武汉220kV电校培训变20261021.scd`，SHA-256 与 P0 一致。

只读 XML 扫描成功，文件大小为 50,418,958 字节（约 48.08 MiB），最后一个元素约在第 1,214,138 行。统计按元素 localName 聚合，仅作为规模观察；正式解析必须同时匹配 namespace URI，不能把厂商扩展中的同名节点当作标准节点。

| 对象 | 数量 |
|---|---:|
| IED / AccessPoint / LDevice | 104 / 216 / 302 |
| LN0 / LN | 302 / 14,944 |
| DataSet / FCDA | 1,036 / 42,688 |
| ReportControl / GSEControl / SampledValueControl | 687 / 205 / 32 |
| ExtRef / Private | 3,194 / 5,131 |
| LNodeType / DOType / DAType / EnumType | 476 / 119 / 19 / 21 |

观察到根命名空间为 `http://www.iec.ch/61850/2003/SCL`，声明了多个厂商扩展命名空间，schemaLocation 指向相对文件 `SCL.xsd`，未观察到根元素的 version/revision/release 属性。不能仅凭命名空间、文件扩展名、Header 的 version 或 schema 文件名判定精确标准版本；Header 中的版本属于该配置文档。

样本中存在未填 daName 的 FCDA，以及形如 `LD0/LLN0$BR$brcbAlarm` 的 rptID。前者不能直接判为字段缺失，后者必须原样显示，不能强制补成 IED 前缀格式。当前未执行 XSD 校验或完整语义检查，不对该样本给出“合格/不合格”结论。

样本不复制到仓库，不上传外部服务，不写回原文件。自动化测试使用自建脱敏小样本；此文件作为本地可选的大文件验收输入，不要求 CI 持有同一绝对路径。

## 3. 面向使用者的 SCL 概念

| 名称 | 产品中的解释与用途 |
|---|---|
| ICD | 设备能力描述；不能套用“全站必须具备所有通信配置”的规则 |
| SCD | 系统配置描述；可浏览多个 IED、网络和关联关系 |
| CID | 面向设备的已配置描述；不应要求包含全站设备 |
| IED / AP | 智能电子设备 / 接入点；同一 IED 可有多个接入点 |
| LD / LN | 逻辑设备 / 逻辑节点；LN 名通常组合 prefix、lnClass、inst，LLN0 需专门处理 |
| DO / DA / FC | 数据对象 / 数据属性 / 功能约束；数据类型模板定义结构，实例节点可能只覆盖部分配置或初值 |
| DataSet / FCDA | 数据集 / 有顺序的成员引用；报告数据解释依赖成员顺序，重复成员也要保留其序号 |
| ReportControl / RCB | 报告控制配置；区分缓冲 BRCB 和非缓冲 URCB |
| rptID / RCB 引用 | 报告标识字符串 / 定位报告控制块的对象引用；分别展示 |
| GOOSE / SV | 与 MMS 分开的通信类型；本期读取其控制块与网络配置，不收发报文 |
| ExtRef | 外部输入引用；可查看发布源和接收端，存在不完整/未绑定情况 |
| DataTypeTemplates | 把 LN 类型关联到 DO、DA、枚举类型的字典；只遍历 DOI/DAI 会漏掉很多模型内容 |

对象引用示例（示意，不代表样本实际对象）：`IED1LD0/LLN0.Mod.stVal`；对应带 FC 的 MMS 变量映射可展示 domain=`IED1LD0`、item=`LLN0$ST$Mod$stVal`。这些字段是按规则推导，界面应区分“原始值”“推导值”“未解析/存在歧义”。LD 名优先依据适用版本的显式 ldName 规则，否则按 IED 名与 LD inst 等规则构造；不得对所有厂家文件只做字符串拼接。

FCDA 可能指向 DO、DA、结构成员或数组成员，不保证一条 FCDA 等于一个标量。详情应显示声明引用和目标结构；结构展开另列子项，保持原始成员索引。完整解析要处理嵌套 SDO/BDA、FC 和数组 ix，防止只按对象名字误连。

## 4. 工作台信息架构与操作流程

### 4.1 布局草图

```text
文件 / 视图 / 帮助          打开  重新加载  校验  取消任务   [全局搜索]
当前文件：名称 · 类型 · 版本识别状态 · 分析状态
┌────────────────┬──────────────────────────────┬─────────────────┐
│ SCL 导航       │ 概览 / 数据集 / 报告 / 对象   │ 属性与引用      │
│ IED > AP > LD  │ 通信 / 类型模板              │ 原始值/推导值   │
│ 按需展开 LN   │ 表格 + 筛选 + 面包屑 + 前后退│ 跳转目标/使用方 │
│ 网络/一次结构  │ 当前对象的关联详情            │ 原文定位        │
├────────────────┴──────────────────────────────┴─────────────────┤
│ 校验问题 / 搜索结果 / 原文预览（可停靠、标签切换）                 │
└─────────────────────────────────────────────────────────────────┘
状态栏：任务进度、错误/警告、Redis 状态（独立区域）
```

所有工作区由 ADS 管理。原有服务器/客户端列表及创建行为保留，通过“视图”菜单切换仿真/文件分析布局，避免新功能挤满主界面。当前文档的多个视图共享一个会话，不为每个叶子节点创建新 Dock。提供“恢复默认布局”，布局版本变更时安全回退。

### 4.2 从打开到定位的主流程

1. 打开文件：仅支持的后缀；确认可读和非空后后台读取。展示阶段及可取消操作；扩展名正确仍可能是错误内容。
2. 分析完成：默认展示概览及“当前规则集”的校验摘要，不自动展开全树，不自动创建服务器或客户端。
3. 查报告：按 IED 筛选报告表，选中 RCB，查看 rptID、数据集、触发条件、可选字段和实例配置；点击数据集进入有序成员表。
4. 查成员：从 FCDA 跳转目标 LN/DO/DA 和类型定义，再通过“被谁使用”返回数据集及报告。前进/后退保存导航历史。
5. 查问题：点击诊断定位对象和原文，解释“发现什么、影响什么、依据什么规则、建议检查什么”。不自动改文件。
6. 关闭或重新加载：后台取消旧任务；只有完整新快照才替换旧会话。新文件失败时保留旧结果并标注它所属文件，展示新文件失败原因；禁止旧任务覆盖新结果。

### 4.3 各视图的内容

| 视图 | 关键内容 |
|---|---|
| 概览 | 文件大小、版本线索、IED/LD/LN/数据集/控制块统计、厂家分布、问题分级、校验覆盖范围；能看到下一步入口 |
| 导航树 | IED → AP → LD → LN，LN 下按数据对象/数据集/控制块分组；另有 Communication、Substation、模板和扩展入口 |
| 数据集表 | IED/AP/LD/LN、名称、描述、成员数、被引用数、问题；成员表显示原始序号、FC、引用、解析状态、说明 |
| 报告表 | 所属路径、name、buffered、原始 rptID、RCB 引用、datSet、confRev、bufTime、intgPd、TrgOps、OptFields、indexed、RptEnabled/max；详细参数放属性区 |
| 对象表 | LN/DO/DA 层级、描述、CDC/bType、FC、数组、枚举、SCL 配置初值、引用与 MMS 映射；初值明确标为配置值 |
| 通信表 | SubNetwork、ConnectedAP、IP/掩码/网关、GSE/SMV 关联、MAC/VLAN/APPID、控制块数据集、ExtRef 源/接收方 |
| 类型/一次结构 | 类型定义及其使用方；Substation 原始层级和 LNode 关联，首期不绘制一次接线图 |
| 问题表 | 严重级别、规则编号、IED/对象路径、位置、原因、建议；支持按范围/级别/规则筛选及导出 |

报告“定义数量”与按 indexed/RptEnabled 等规则得到的“可能实例数量”分开显示。未验证实例化规则前，实例引用只标为候选，不将定义数量误称为可连接实例数量，也不把推导 rptID 当作设备实际返回值。

### 4.4 搜索和原文预览

- 全局搜索覆盖名称、中文描述、标准对象引用、MMS 映射、rptID、数据集名、IP、APPID 和问题；支持按 IED、对象类型、FC、严重级别过滤。首期采用普通文本子串搜索与精确匹配，不引入复杂表达式语言或无限制正则。
- 分清“当前表格筛选”“模型全局搜索”“原文文本搜索”。首期前两者必做；原文全文搜索单独后台流式执行，可作为后续增强，不宣称模型索引能覆盖任意 Private 文本。
- 搜索输入建议 200 ms 防抖；结果表分页/分批加载，显示完整命中数或“仍在搜索”，不能把截断数量冒充总数。搜索同时覆盖尚未展开的树节点。
- 结果包含对象类型、完整路径、匹配字段和片段。点击后展开祖先节点并选中对象，联动表格、属性和原文；树未展开不影响检索完整性。
- “特殊对象”默认包含 FCDA、ReportControl、DataSet、GSEControl、SampledValueControl、ExtRef、类型定义和诊断目标；其他节点也支持查看原文。
- 原文只读，默认显示目标上下各 15 行，带行号、高亮和“更多上下文”；超长元素只显示有限窗口并提示截断，不能一次把百万行装进文本控件。没有 daName 等属性时定位所属起始标签。
- 保存原始字节快照并建立编码感知的行索引；识别 XML 声明/BOM，覆盖 UTF-8、UTF-16 和可验证的常见厂家编码，不识别时明确报错。预览不得把重新序列化的 XML 当作原文。
- 解析器的行列/characterOffset 不等于原始字节偏移，且 token 位置未必是起始标签开头；需建立并测试 source span 映射。第一阶段至少准确定位元素行，精确属性高亮需通过多行标签、中文、CRLF、注释和 CDATA 测试后启用。
- 文件外部修改时提示重新加载；预览和诊断始终对应同一快照，不能用旧索引读取新磁盘内容。

## 5. 校验产品设计

### 5.1 分层与完成状态

| 层次 | 检查 | 能力与限制 |
|---|---|---|
| L0 文件/XML | 可读、非空、格式、编码、根元素、命名空间、安全限制 | XML 损坏后停止语义检查，保留失败位置及可预览原文；不把不完整模型呈现为完整成功 |
| L1 基础结构 | 各节点及属性的基础必需项、局部结构与可解释性 | 按已明确的版本/文件配置应用规则；不能替代完整 XSD |
| L2 引用一致性 | 类型、FCDA、控制块到数据集、网络到 AP/控制块、ExtRef 等 | 区分未绑定、文件范围外、确实悬空及歧义；识别失败时不得静默取第一个目标 |
| L3 工程提示 | 空数据集、未使用对象、通信异常、疑似配置冲突、重复报告标识等 | 仅作规则内建议；重复值需按作用域分析，未使用对象不一定错误 |
| L4 XSD（后续独立门槛） | 按明确标准版本进行 schema 校验 | 需要合法取得并固定的 schema 和验证引擎；未接入显示“未执行”，不能显示“标准校验通过” |

本期 MVP 必须具备 L0～L2 的明确子集和少量 L3 提示，公开规则目录。L4 单独立项/子阶段：先核验 XSD 版本、获取及分发条件，再选择引擎；Qt 流式 XML 解析本身不执行 XSD 校验。[IEC Code Components](https://iec61850.dvl.iec.ch/61850-resources/61850-code-components/) 提供有关 XSD/NSD 等组件的说明。

校验摘要使用“本轮已执行 N 条规则：错误 E / 警告 W / 提示 I；未执行或不适用 K 条”，同时显示版本识别与覆盖范围。没有发现错误应表述为“已执行规则未发现错误”，避免“文件完整且完全符合 IEC 61850”的结论。

### 5.2 首批规则目录与严重程度

| 建议编号 | 内容 | 默认处理 |
|---|---|---|
| XML001～004 | 空/不可读、XML 语法失败、根元素或命名空间不支持、DTD/外部实体限制触发 | 阻断对应分析，错误 |
| STR001 | IED、LD、LN、DataSet 等关键命名属性缺失 | 已明确规则时为错误；版本/方言未知时说明覆盖限制 |
| KEY001 | 相同合法作用域内重复定义，导致引用歧义 | 错误；不同 IED 的同名数据集不误报 |
| TYP001～003 | lnType、DO/SDO/DA/BDA/Enum 类型引用不存在、循环或深度越限 | 错误；防止无限展开 |
| REF001 | 控制块 datSet 非空但无法在适用作用域解析 | 错误；空/缺省是否允许需结合版本和服务能力，不一概判错 |
| REF002 | FCDA 的 LD/LN/DO/DA/FC/数组索引无法解析或不兼容 | 错误或受限诊断；缺 daName 不直接报错，实例缺 DOI/DAI 也不等于模型不存在 |
| REF003 | ConnectedAP 或 GSE/SMV 的控制块映射失效 | 对应范围可判定时为错误 |
| REF004 | ExtRef 源定位失败 | 按版本、是否绑定及当前文件覆盖范围定级，不将所有未绑定输入判为错误 |
| ENG001～004 | 空数据集、未使用定义、可疑 IP/MAC/VLAN/APPID、同作用域报告标识冲突 | 默认警告/提示；APPID 按通信类型/网络作用域和冗余配置评估 |
| VER001 / EXT001 | 版本不明、未知标准节点/厂商扩展导致覆盖不足 | 提示并列明未检查项，保留扩展原文 |

每条规则在实现时补齐：依据及版本、适用文件类型、前置条件、严重度、正反例、例外和测试。错误表示当前任务无法可靠解释某部分，并不等同于设备一定不能运行。厂商兼容配置可显式选择并记录，不静默降低规则。

如果用户真正关心的是“少了哪些保护测点、设备、报告或工程约定”，需后续提供点表、设备清单、基准文件或工程规则模板。单份 SCL 只能判断其内部关系，无法推断现场设计意图。

## 6. 技术方案与目录边界

```text
MainWindow / ADS Dock
    → SclDocumentViewModel（GUI 线程：选择、筛选、任务状态）
    → SclAnalysisService（打开、解析、取消、版本化结果）
    → 后台：SclReader → SclDocument → ReferenceResolver → SclValidator
                                ├─ SearchIndex
                                └─ SourceIndex / 原始快照
    → 不可变结果通过 queued signal/slot 或 QFutureWatcher 回 GUI
```

建议新增文件，遵守 UpperCamelCase：

- `src/iec61850/scl/`：`SclReader.*`、`SclDocument.*`、`SclReferenceResolver.*`、`SclValidator.*`、`SclSourceIndex.*`；属于共享领域能力，不直接访问控件或 Redis。
- `src/core/`：`SclAnalysisService.*`，负责会话、后台任务、取消和结果交付。
- `src/gui/`：`SclDocumentViewModel.*`、`SclTreeModel.*`、`SclTableModel.*`、`SclWorkspace.*`、`SclSourcePreview.*`，主窗只装配和路由。
- `tests/fixtures/scl/`：自建微型有效/异常样本；`tests/unit/` 测解析、解析引用、规则和映射；`tests/integration/` 测工作流和可选真实大文件。

解析优先使用 Qt Core 的 `QXmlStreamReader`，匹配 namespace URI + localName，保留未知扩展的位置和必要元数据。它是前向流式读取器，能提供行列/字符偏移；API 及实体限制见 [Qt 官方文档](https://doc.qt.io/qt-6/qxmlstreamreader.html)。只使用本项目实际 Qt 版本支持的 API，不依赖较新版本才有的原文读取接口。

模型采用稳定 NodeId、父子关系、类型定义索引和有序成员，NodeId 至少含文档会话/节点标识，不只靠名称。引用解析使用完整上下文（IED、AP/Server、LD、LN、类型/FC、数组等）及作用域规则；将“原始引用字符串”“规范化目标”“候选目标/失败原因”分开存储。

模板按需实例化、共享类型结构，不为每个 IED 完整复制全部模板树。解析先建索引，再解析前向引用，避免文档顺序影响结果。DOI/SDI/DAI 与类型模板组合展示，区分配置实例覆盖和模板默认值，不能把缺少实例覆盖误报为数据缺失。

初期使用内存索引，不引入 Redis/数据库作为打开文件的前提。领域结果不可变，UI 的 QModelIndex 不跨线程传递；Qt Item Model 仅在 GUI 线程创建/更新。取消用任务 ID + 协作标记，解析/索引/校验分批检查；窗口销毁不捕获悬空 GUI 对象。

安全与资源边界属于导入实现的一部分：拒绝 DTD、不解析外部实体、不跟随 schemaLocation 联网或任意读取本地文件；限制文件大小、节点数、深度、文本长度和模板递归。初始建议文件上限 256 MiB、XML 深度 256，其他阈值按真实样本测量后固定；超限要明确诊断而非静默裁剪。若后续接入 XSD，引入独立的本地白名单 catalog。

## 7. 视觉和交互设计

采用克制的工业工具风格：浅中性背景、清晰分栏、蓝绿色选中态；红/橙只表达错误/警告，同时配文字和图标。界面中文解释，保留 FCDA、rptID 等原始术语；对象引用和 XML 使用等宽字体，长路径可复制并提供提示。表格首列固定身份信息，默认列数受控，稀有字段进入属性区。

初始设计尺寸：8 px 间距基准、28～32 px 表格行高、14 px 左右正文；以系统字体和 DPI 缩放适配，在 1280×800、1920×1080、100%/150%/200% DPI 下验收。多选复制、列排序、键盘导航、可见焦点和空/加载/失败/取消状态与正常内容一起设计。

[finesse-skill](https://github.com/mouse-lin/finesse-skill) 的 product 路线强调信息密度及组件状态，可作为排版和层级参考；本项目选择高密度桌面工具方向。[GSAP Skills](https://github.com/greensock/gsap-skills) 主要面向 JS/Web 动画；这里仅借鉴短反馈和减少动效的原则，Qt 原生动画按需实现约 120～180 ms 的轻反馈。避免表格逐行入场、长转场和持续装饰动效，提供关闭动效选项。

本轮无需安装这些参考 skill。后续确需安装时按用户要求采用 Codex 全局范围，不往项目植入 Web 框架；安装与运行时依赖是两件事。

图标建议固定单一开源系列，先核验具体图标集许可证再选定。可通过 [Yesicon](https://yesicon.app/zh-Hans) 选型，但不能把聚合网站视作全部图标的统一授权。上游图标源码/许可证/来源/版本备份至 `third_party/`，应用资源纳入 `resources/`，通过 Qt 资源系统离线加载；自制 SVG 保持相同笔画。若使用 SVG 运行时渲染，在接入阶段补齐 Qt Svg 依赖和部署验证。[Aha Icon](https://ahaicon.com/zh/) 可供应用标识风格参考，首期不依赖在线生成服务。

## 8. 性能目标与测量方式

以下是待验证的工程目标，不是当前实测能力；以同一开发机、Debug 构建、上述约 48 MiB 样本记录基线，并附 CPU/内存/Qt/编译器信息。

| 场景 | 初始验收目标 |
|---|---|
| 打开至可浏览核心模型 | 10 秒内；XML、索引、校验阶段可见且可取消，后续完整校验单独记录 |
| 导航、切换表格、选中对象 | 常见操作 100 ms 内反馈；不因展开大量子项阻塞 GUI |
| 已建索引后的普通搜索 | 首屏 300 ms 内（不计输入防抖），完整命中数可随后更新 |
| 原文窗口定位 | 已建行索引后 200 ms 内显示窗口，不读入完整百万行控件 |
| 取消、关闭会话 | 500 ms 内响应；协作任务及时退出，旧结果不回填 |
| 资源 | 目标增量峰值内存小于 600 MiB，记录峰值与模型规模；连续打开/关闭 10 次无持续增长 |

QTreeView/QTableView 使用模型、懒加载和 delegate；避免每行一个 QWidget、全树 QStandardItem 预展开或在主线程做大规模代理递归筛选。测量不达标时先优化模型/批次/索引；不通过隐藏未解析对象换取性能。超大文件和资源不足场景要可取消、可解释失败。

## 9. 分阶段执行方案与验收门槛

阶段必须顺序通过；每阶段独立可构建、可评审。现有 CMake/ADS/Redis 门槛先复核，不能把新 XML 引擎、全新界面与协议功能一次性并入。

| 阶段 | 交付 | 进入下一阶段前的验证 |
|---|---|---|
| P0 基线与规则准备 | 核验当前 Debug/现有测试；建立自建样本、规则目录与样本统计基线；整理文档中当前/未来范围 | `windows-debug` 配置、构建、CTest 通过；现有列表/布局/Redis 两类启动路径无回归；不改 tools/Redis；记录真实样本读取与版本不明事实 |
| P1 无 UI 的流式解析与源索引 | SclReader/Document/SourceIndex，IED/LD/LN、模板、数据集、报告、通信和扩展元数据 | 小样本精确断言；真实样本按 namespace 复核数量；编码/命名空间/坏 XML/超限/原文行定位测试通过，测量时间与内存 |
| P2 引用解析与基础校验 | 类型/FCDA/数据集/通信/ExtRef 索引、诊断规则、报告/MMS 映射 | 前向引用、同名不同作用域、缺 daName、显式 ldName、结构/数组、模板循环、歧义和未绑定正反例通过；覆盖/未执行项可追溯 |
| P3 应用服务与任务生命周期 | 异步加载、取消、重新加载、不可变快照、状态与进度 | 加载期间 GUI 可响应；快速切换文件、取消、失败后保留旧文档、关闭窗口均无过期结果/崩溃；Redis 不可用仍可分析 |
| P4 ADS 分析工作台 | 概览、树、数据集/报告/对象/通信表、属性、源预览和双向引用 | 真样本完成“报告 → 数据集 → 成员 → 类型 → 原文 → 返回”；所有节点/问题入口能定位；原有仿真占位入口保持可用 |
| P5 搜索、问题导出与视觉统一 | 全局搜索、筛选、前后退、问题面板、JSON/CSV 校验摘要导出、图标和轻动效 | 未展开节点能搜到；特殊字符/中文搜索、空结果与取消正确；导出包含文件指纹/规则版本/覆盖/原文位置，CSV 正确转义并防止公式执行；键盘/DPI/大文件性能验收 |
| P6 收尾与发布验收 | 布局版本化/恢复、默认布局、帮助、文档、回归结果 | 重启恢复有效静态布局；文件不自动重新打开时动态文档视图安全跳过；损坏布局回退；正常/无 Redis 重复启动；10 次文件循环与完整 Debug/CTest 通过 |

P1～P2 的可测试静态库可由根 CMake 单独挂接，无需先改主窗。P4 之前先固定一套表格字段和导航原型，再实现主题细节。完整 XSD 作为后续 P7：依赖/许可证/版本门槛 → 离线引擎原型 → 测试 → UI 状态接入，不能用 P1 的成功替代 P7。

最小测试矩阵应覆盖：合法最小 ICD/CID/SCD、供应商 CCD/不识别方言、错误扩展名/伪装 XML、空文件、截断 XML、重复键/悬空引用、缺省可选属性、完整与不完整类型实例、模板环、命名空间别名/扩展同名节点、不同编码/行尾/多行标签、同名多 AP、BRCB/URCB/indexed、超大文件/取消/重载竞争、布局和无 Redis 启动。CCD 没有真实样本前只验收明确的“不支持该方言”诊断路径，不宣称已兼容。

验收以两条用户任务为准：① 搜到一条报告并查清它上送哪个数据集、成员在哪里定义；② 从一条校验问题跳到对应对象和原文，并理解修复方向。规则单测、集成任务及 GUI 验收共同提供证据，不用仅比对截图替代解析正确性。

## 10. 后续驱动开发的任务写法

每次给开发 Agent 一个阶段及明确门槛，例如：

> 按 docs/Tasks/Task1.md 执行 P1；先确认 P0 已通过。只实现离线 SCL 解析、模型和原文行索引，不接入 GUI 或设备通信。保留用户现有改动，不修改 tools/Redis。使用自建脱敏样本验证 namespace、编码、坏 XML、模板及数据集/报告提取，使用真实 SCD 做本地规模核验。报告改动、测试命令/结果、性能实测、已覆盖/未覆盖范围，同步 README、AGENTS 和 DEVELOPMENT。

每阶段完成时报告“已完成 / 验证结果 / 未覆盖项 / 下一阶段入口”。依赖新增必须同时备份库源码、许可证、版本和来源至 `third_party/` 并更新 `third_party/DEPENDENCIES.md`；独立程序管理于 `tools/`。本提案没有新增实际第三方依赖。

## 11. 可补充信息与默认决策

以下信息对方案有帮助，但不阻碍先实施基础解析：

1. “MMS 报文 ID”的实际字段或界面示例：默认理解为 MMS 对象标识；如指 Invoke ID，则另开在线通信/抓包任务。
2. 常见文件来源、标准版本和 CCD 小样本：默认优先兼容当前 SCD，版本未知时保守检查并明确提示。
3. 是否有厂家/项目点表、工程检查规范或已知错误样本：默认只做内部一致性，不承诺工程测点完整性。
4. 是否必须完整 XSD 合规校验：默认作为后续 P7，MVP 明确标注未执行；若为交付硬要求，应前移 P7 并重新评估依赖和交付范围。
