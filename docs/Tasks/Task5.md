## 3. 表格的统一交互契约

### 3.1 双击复制与导航

范围为 SCL 工作台内所有只读数据表：任务页、GOOSE/SV 成员、收发关系、高级业务表、引用候选、问题和搜索结果。树、图节点、按钮和显式链接不属于“单元格复制”范围。

| 操作 | 预期行为 |
| --- | --- |
| 单击单元格 | 选中行并更新详情；记住实际点击的列 |
| 双击单元格 | 复制该单元格对应的完整文本值；不复制整行、不编辑、不打开原文 |
| Ctrl+C / 右键“复制单元格” | 复制当前单元格，与双击一致 |
| 右键“复制行” / Ctrl+Shift+C | 按当前可见列顺序复制整行，单元格间用制表符；明确区别于复制单元格 |
| 字段旁“原文”、引用旁“定位” | 显式打开相应证据或目标，不依赖双击数据内容 |
| Enter | 激活明确标注的“定位/原文”动作；无唯一目标时展示候选，不选第一个 |
| 图节点双击 | 保留 Task4 原文跳转；不因表格改动而改变图节点的约定 |

复制规则：

- 复制对应字段的原始字符串或明确标注的完整派生值，不复制图标、颜色标签、HTML 转义、显示用前缀或自动换行；原文自带换行保留。APPID 原始格式、大小写与前导零不能擅自改写。
- 空字段显示“未声明/无可复制内容”，不覆盖剪贴板为提示语。派生值与原值同时显示时，菜单明确提供各自复制入口。
- 短暂显示“已复制：对象引用（N 字符）”，不弹阻塞对话框，不把工程内容写入日志。
- 必须解除旧的鼠标 `activated` 跳转路径；不能简单同时连接 `doubleClicked` 和 `activated`。事件分流需要覆盖双击产生的选择、激活与键盘事件，避免复制后又导航。
- 复制目标由快照、表类别、作用域、原始行身份、列/字段身份确定，不能只保存可见行号。长值按用户请求在后台取完整内容，核验请求仍有效后写入剪贴板；不能在 GUI 线程重新读文件。

建议定义独立 `CopyValueRole` 或完整值定位器，和 DisplayRole 分开。现有 `.left(512/2048)`、路径分段预算及详情截取需要逐一核对；关闭省略号不等于恢复了上游被截断的值。CSV 防公式处理继续只适用于相应导出流程，不能污染用户主动复制的原字段。

### 3.2 单元格换行与行高

默认开启完整换行和顶部对齐。中文按正常断行，长对象引用、MMS Item、MAC 等没有空格的文本也允许在必要位置断行；不向字段插入真实换行字符。列宽可拖动，技术引用使用可读字体和适当宽度，描述列与路径列承担主要伸缩。

仅设置 `wordWrap=true` 不足以满足要求：Qt 明确说明单元格不会自动长高，仍可能按 textElideMode 省略。[Qt QTableView 文档](https://doc.qt.io/qt-6/qtableview.html#wordWrap-prop)。实现需同步取消省略、正确测量文本高度并更新实际行高。

性能方案：

1. 关系成员已有 200 行分页，可对当前页精确测高；大规模信号/高级表只测量可见行和少量预取行，不对全表反复 `resizeRowsToContents()`。
2. 用共享 delegate/文本布局计算高度，按正常词边界及必要的任意位置换行；不为每个单元格创建 QLabel、QTextEdit 或其他 QWidget。
3. 缓存键包含快照、表类别、作用域、原始行/字段身份、列宽、字体和缩放代次。拖动列宽时合并重排请求；更换字体/DPI/文档时正确失效。
4. 用“顶端原始行身份 + 行内偏移”保持滚动锚点。可变行高不能导致定位到旧行、滚轮跳回顶部或历史偏移失真；搜索跳转后须等目标行测高再完成滚动。
5. 普通业务字段不采用固定两行/三行上限，不用 `…` 代替内容。异常超长值超过展示预算时明确显示“完整值 N 字符”及独立可滚动全值页，不伪装成已完整显示；其全文仍可按需复制。这是资源边界，不得套用于普通描述和引用。
6. 变高会降低单屏行数，提供列显隐、合理默认列宽及可收起详情，而不是重新裁切文本。QHeaderView 对行高修改的额外内存开销纳入基线。[Qt QHeaderView 文档](https://doc.qt.io/qt-6/qheaderview.html)。

## 4. 统一的描述来源与字段含义

### 4.1 描述层次

SCL 中对象描述和属性描述不是同一个字段。以合成对象 `PTRC1.Tr.phsA` 为例：对象描述可以是“跳闸出口”，属性描述若未声明，不能把“跳闸出口”冒充 phsA 的原始 desc。可以分别显示“对象描述：跳闸出口”“属性：phsA”“术语释义：A 相分量”，并标明释义来自内置词典。

| 类别 | 取值与来源 | 展示要求 |
| --- | --- | --- |
| 实例对象描述 | 唯一匹配的 DOI/SDI 中 dU 的非定值组 Val，且类型声明确认语义；或该实例的 desc | 保留原始值、来源类别和原文入口 |
| 模板对象描述 | 当前 LN 实例实际使用的 DO/SDO 声明 desc；适用时单列 DOType desc | 标明“模板”，不冒充实例专用信息 |
| 属性描述 | 匹配到的 DAI/SDI 或 DA/BDA 声明 desc | 与 DO 描述独立，品质、时间等附属属性仍归所属对象 |
| 成员声明描述 | 当前 FCDA 自身声明的字段，若该格式确有提供 | 与解析目标的描述分开，不假设每条 FCDA 都有 desc |
| 技术释义 | 有版本的字段/枚举词典，如 FC、CDC、phsA | 独立标为释义，不称为厂家描述或工程确认 |

建议默认标题优先选择唯一实例 dU，其次实例 desc，再其次模板 DO/SDO desc；DOType desc 只作为单独的类型说明。空值、缺失、无法定位、歧义分别保留。不同来源有不同文本时显示“多来源描述”，展开可并列查看；这是差异，不自动报告工程错误。

不保证中文描述，外文原文保留；不通过在线翻译或模型编造中文。缺失时标题用对象名称，描述栏明确“未声明描述”。内置术语说明放在帮助/释义区，不每选一行重复一段通用科普。

### 4.2 描述解析服务

建议在 Qt Core/应用服务侧形成共享 `SclDescriptionResolver` 和只读投影，供信号、FCDA 成员、GOOSE/SV、关系详情及搜索共用，避免各页各自选择来源。

每个描述项至少含：所属 LN 实例、对象/属性路径、FC/数组语境、原始值、来源类型、来源 NodeId、状态、候选来源、是否适用定值组、规则版本。结果绑定文档快照。

必须覆盖：

- 没有数据集成员使用的信号仍能读取实例/模板描述，不能只查第一条 FCDA 的 instanceDescription。
- 同模板被多个 LN/IED 复用时区分实例；名称相同但 AP/Server 不同不能混用。
- 多个 Val、sGroup、数组实例和多候选不取第一个。未展开元素或无法唯一定位时展示受限原因，不从相邻节点借描述。
- 对象、属性、类型与成员声明的描述分别存储。重复成员共享目标说明但保留各自原始序号及声明来源。
- 描述索引在后台建立，结构共享和有界缓存优先；不得为所有信号预复制大段富文本。GUI 的 `data()` 不遍历 XML、展开类型或做引用搜索。

### 5.2 工作对象与原文查看对象

设立明确的两种上下文：

- **工作对象**：当前选中的信号、流或成员，决定表格/详情内容。
- **原文查看对象**：当前打开的实例、模板或字段证据，是工作对象的证据，或者一次独立结构浏览。

从字段打开原文时标题应为“工作对象 A → 字段 B 的模板定义”，附来源路径及返回操作。直接在左树选择无对应业务行的模板时显示“结构浏览：DA serNum”，同时保留“返回所选信号 A”；不能无提示地让两组内容看起来属于同一个对象。

共享模板不反向选择任意实例。筛选遮挡时清除旧行高亮并标明遮挡；可以显式清除筛选定位。切换工作对象时立即清空旧详情或显示新对象的加载态，失败后标注新对象加载失败，不保留上一对象正文冒充新结果。

描述/详情/原文异步交付核验快照、请求代次、工作对象键及作用域；历史恢复这些身份与滚动锚点。新方案保留 Task4 的独立 ADS 管理器和生命周期约定。

## 7. 视觉规范与状态

沿用 finesse-ui 的产品信息密度与现有系统字体，保留 Widgets 原生键盘和焦点行为。以对齐、分组、稳定标题及留白改善阅读，不以增加大卡片、渐变、动效代替组织。

## 8. nodeeditor 能解决什么

### 8.1 评估结论

[paceholder/nodeeditor（QtNodes）](https://github.com/paceholder/nodeeditor) 可以帮助实现端口式节点和连线交互。官方文档区分纯图展示的 `AbstractGraphModel + BasicGraphicsScene` 与数据流执行模型；本项目如果接入，应选择前者作为只读图适配，不需要让 SCL 对象变成自动执行的数据流节点。[QtNodes 官方文档](https://qtnodes.readthedocs.io/en/master/)

它适合后续将“装置/发布流”画为节点，将成员或成员组画为端口；可减少通用节点绘制和交互代码。它不能补全缺失描述、解析 SCL、确认候选绑定或自动解释保护功能。换库也不会自动解决表格与详情的上下文问题。

| 选项 | 价值与代价 | 本任务建议 |
| --- | --- | --- |
| 现有 QGraphicsView | 已有部署，局部图足够使用；端口/布局需自己维护 | 先继续使用，表格与详情改进不等待绘图库 |
| QtNodes 只读适配 | 更完整的节点/端口交互；需验证禁用编辑、适配图身份及部署 | T5.5 做隔离试验，有明确收益再接入 |
| QML / 前端替换整个工作台 | 可定制更多视觉效果，但需要新依赖、桥接与同快照交互维护 | 本任务不更换外壳；后续有实测需求再单列 |

不能仅隐藏编辑按钮就宣称只读。试验必须从模型、场景及快捷键三层验证：禁止新增/删除/重连、粘贴、拖入节点和编辑撤销；可允许节点位置移动作为当前图的临时视图状态，不能写入工程或改变逻辑连线。

### 8.2 依赖与兼容门槛

本次只查阅上游，未下载、安装或编译 nodeeditor。实际采用时固定经验证的 v3 标签/提交，不直接跟随 master；当前工程 UCRT64/Qt 6.12 的兼容性不能由上游列出的 Windows MSVC 环境代替。

所查 master 的 CMake 请求 Qt Core/Widgets/Gui/OpenGL，并有通用 BUILD_TESTING、BUILD_EXAMPLES 等选项。上游 external 中 Catch2 仅在构建其测试时处理。接入时隔离选项作用域，不能误关根项目测试或把 ADS 改为静态；禁用上游示例/文档后验证完全离线构建。[上游构建文件](https://github.com/paceholder/nodeeditor/blob/master/CMakeLists.txt)、[测试依赖配置](https://github.com/paceholder/nodeeditor/blob/master/external/CMakeLists.txt)

源码、归档指纹、来源和许可证保存于 `third_party/` 并记录到 `third_party/DEPENDENCIES.md`。当前上游为 BSD-3-Clause，必须按所选提交复核并随分发保留声明；内部附带的其他组件也需核对其许可。静态链接与否在试验后决定，DLL/插件通过现有 CMake 部署，清洁 PATH 启动验证。本任务无新增独立运行程序需求，不接触 E 盘工具目录和 Redis 迁移。[上游许可证](https://github.com/paceholder/nodeeditor/blob/master/LICENSE.rst)

## 9. 是否需要图结构与图算法

建议使用**有类型的有向多重图投影和轻量图算法**，不必为了这些查询引入图数据库或通用图算法库。已有 incoming/outgoing、controlsByDataSet、memberLinks 等就是可复用的图基础。

### 9.1 图中的身份与边

节点至少区分 IED/AP/Server、LN 实例对象、发布流、数据集成员出现位置、ExtRef 接收输入和模板证据。FCDA 节点用“数据集 NodeId + 原始成员序号”，不能把两次相同引用折叠成一次。图 ID 与 QtNodes 的 ID 之间建立适配映射；不直接将模板 NodeId 当作实例或把库的布局编号当领域身份。

边分别表示：声明归属、已解析引用、明确成员绑定、成员匹配候选、DO/DA 包含候选、描述/类型来源。携带源/目标证据、快照、规则版本和限制；共享模板边不参加“实际发给谁”的遍历。连接多端点保留各自身份。

| 方法 | 产品用途 | 不应推出的结论 |
| --- | --- | --- |
| 正反向邻接索引 | 从信号查使用，从输入查来源，从发布流查接收方 | 没有边不等于现场没有接收 |
| 有界 BFS/DFS | 展开上游/下游若干层、找同一成员的使用位置 | 跨 IED 的最短配置路径不等于保护动作链 |
| 按 IED/服务/发布流聚合 | 首屏显示装置与流摘要，逐层展开端口，控制交叉线数量 | 相同 APPID/名称不能直接合并为同流 |
| 按语义分层布局 | 发端 → 发布流/成员 → 收端，固定方向并稳定排序 | 视觉布局不改变领域引用和原始成员顺序 |
| 连通分量/SCC（后续按需） | 将复杂图分区，循环关系布局时避免递归失控 | 装置互相订阅或存在环不自动构成工程错误 |

特别限制：同一 PL 装置既接收 SV 又发送 GOOSE，不能仅凭同属该 IED 就推断“这个 SV 输入导致那个 GOOSE 输出”。本文件若没有功能逻辑证据，界面只展示两组通信关系，不串出虚构的因果链。

### 9.2 展示预算

保留 Task4 的明确/候选分离和后台索引；新图每次先交付约 80 个节点、160 条边的局部投影，逐层扩展需另一次可取消请求。预算值在 T5.0/T5.5 实测后固定，不作为已取得的性能结果。被折叠端口及隐藏关系显示数量与“展开更多”，不静默漏掉内容。

节点在布局中合并显示时保留成员身份映射，点边能定位到原始成员和接收输入。图、表格、详情使用同一个业务选择目标；所有新增布局/展开结果核验快照、代次、根对象与过滤范围。首版用 C++/Qt 容器实现邻接与有界遍历，不增加 NetworkX/Python 运行时或外部图服务。
