# Task2 · SCL 分析工作台视觉与交互优化

2026-11-06 · T2.0 至 T2.4 已实施。见 [基线与样式小样](Task2T2.0.md)、[导航与历史](Task2T2.1.md)、[详情与原文](Task2T2.2.md)、[交互式引用拓扑](Task2T2.3.md)及[视觉收尾与回归](Task2T2.4.md)。现有分析能力见 [Task1](Task1.md) 与 [P6](Task1P6.md)。

## 1. 产品目标与范围

让工程人员从「找到设备或配置项」走到「确认它引用了什么、在哪里声明、检查覆盖了哪些内容」。以整站 SCD 的排查为主要场景，同样支持 CID、ICD、CCD。保留现有只读打开、重载、关闭、全局搜索、表格筛选、问题导出和 ADS 工作区。使用 Task1 的解析及内部一致性规则。完整 XSD 继续由 Task1 P7 单独交付，概览持续展示执行覆盖。运行时 MMS 实例、抓包和设备通信留给独立任务。

需求足以启动设计。需要把「缺失」和「MMS ID」拆成有明确依据的字段，也需要区分「树选择后显示详情」和「树选择后定位主表」。后者是本次联动重点。无需额外文件或视觉规范才能实施。初版采用中文界面、保留工程缩写、浅色中性配色和紧凑布局。如后续要匹配现有品牌、强制暗色主题，或对照某厂商的在线 MMS 工具，再补充规范、典型操作和期望字段。

### 四条主要操作路径

1. **沿设备找配置。** 在导航树展开 IED → LD → LN/LN0，中央显示该节点概览和可进入的下级类型。选择报告定义后定位「报告」行，右侧显示原始标识、数据集和派生映射。
2. **按标识反查。** 在全局搜索输入名称、对象引用、rptID 或现有 MMS 映射字段。结果显示类型、命中字段和设备上下文，区分同名条目。跳转后可返回前一个位置。当前表格筛选与全局搜索保留独立入口及范围说明。
3. **从问题回查原文。** 按严重级别或规则过滤问题，激活结果打开诊断对应的原文位置。详情解释触发规则、引用来源和处理结果。有歧义时展示候选，由工程人员选择。
4. **在图中追查来源和使用方。** 从报告、数据集、FCDA 或可解析对象打开「引用拓扑」，查看字段来源、同数据集成员及共享目标。点选节点或连线可读出处和解析依据。

## 2. 工作台布局与视觉

```text
文件名 · 加载/磁盘变更状态           全局搜索       后退  前进
┌─────────────────┬────────────────────────────┬────────────────────────┐
│ 导航树          │ 当前对象的可点击层级路径   │ 当前对象 · 类型        │
│ ▾ IED           │ 概览 数据集 报告 对象 …    │ 属性  引用  原文       │
│   ▾ LD          │ 表格筛选 · 可见/总行数      │ 声明 / 推导 / 状态     │
│     ▾ LN0       │                            │ 或 XML 上下文          │
│       数据集    │ 按需加载的列表或节点概览    │                        │
└─────────────────┴────────────────────────────┴────────────────────────┘
校验摘要 · 错误 / 警告 / 提示 · 检查覆盖入口
```

- 复用现有 ADS 工作区与内部 splitter，初始宽度可按约 22% / 45% / 33% 试调。优先保留表格的名称和状态，长路径中段折叠并支持展开、复制。窄窗允许缩小或收起详情区，通过明确按钮恢复。失败、加载、空表与筛选无匹配各有独立提示。
- 用浅灰背景、白色工作面、细分隔线及统一的悬停、选中、键盘焦点状态建立层次。LD 用蓝、LN/LN0 用青、DO 用紫、DA 用中性灰作为候选色；类型名或标签同步出现。诊断颜色与类型颜色分开。Qt 逻辑像素初值为 8 px 间距、16 px 图标、28–32 px 行高，由 DPI 与长中文验收调整。保留系统字体，原文使用等宽字体。
- 统一一套线性工具图标，先覆盖打开、搜索、返回、定位和复制。可从 Yesicon 选同一上游图标集并核验上游许可，或自制 SVG。随项目提供的外部素材记录来源、版本和许可证。Aha Icon 用作应用图标构思参考。 [Yesicon](https://yesicon.app/zh-Hans) · [Aha Icon](https://ahaicon.com/zh/)
- 借鉴 Finesse 的界面细节打磨和 GSAP Skills 的反馈节奏。仅在显隐等有明确反馈价值的场景试用约 120–160 ms 过渡，提供关闭动效的方式。树、表格及搜索跳转即时完成。运行时使用现有 Qt 能力。 [Finesse](https://github.com/mouse-lin/finesse-skill) · [GSAP Skills](https://github.com/greensock/gsap-skills)

## 3. 内容如何表达

| 内容 | 展示规则 |
| --- | --- |
| 对象层级 | 面包屑逐段显示实际存在的祖先，例如 IED → LD → LN → DO → DA。逐段可定位，使用类型文字和颜色。提供复制完整路径。 |
| 引用关系 | 在「引用」页展示来源到目标，例如报告定义 → 声明的数据集名 → 已解析数据集。FCDA 可展示 LD → LN → DO → DA 的解析链，并附 FC。路径段只有对应快照中存在可定位节点时才可跳转。分隔符是视觉表达，复制引用使用完整原值或完整推导值。 |
| 解析结果 | 已解析、缺失、歧义、受限分别用文字表达。歧义段显示候选及作用域，缺失段显示原始声明和原因。只展示分析层提供的证据，推导字段保留来源和状态。 |
| 报告与 MMS | 分栏显示报告定义名、原始 `rptID`、数据集引用、派生定义引用、派生 MMS domain/item。对象行同样区分对象引用与派生 MMS domain/item。界面使用这些具体名称来替代宽泛的「MMS 报文 ID」「MMS 报告 ID」。区分「未声明」「无法推导」和「需在线确认」，运行时实际报告标识留待设备会话取得。 |
| 校验 | 概览分开显示 XML 读取结果、内部一致性结果、XSD 检查状态。问题行给出级别、规则 ID、作用域、定位和原因。缺省字段根据现有规则处理，例如缺省 `rptID` 本身不直接报错。「已执行规则未发现问题」与「完整 XSD 未执行」可同时显示。 |

### XML 原文

复用 `SourceIndex` 与只读 `QPlainTextEdit`，只加载目标行附近的有限窗口，首版保留前后各 15 行。行号放在独立边栏，截断提示与可复制 XML 分开。语法层区分标签、属性、值、注释、CDATA 和实体，定位行使用独立背景。LD、LN/LN0、DO、DA 的语义颜色优先用于树、路径与类型标签，原文中只有确认对应标准元素的标签可加同色强调。

用 `QSyntaxHighlighter` 维护窗口内跨行状态。窗口起点若位于多行注释、CDATA 或属性内且无法可靠获得词法状态，未知部分以普通文本显示，直到可靠同步；验证失败文件也可安全预览。长行截断后保留真实行号，若目标超出可见文本，明确提示只定位到行。原文和诊断均绑定来源快照，失败文件预览单独标识。 [Qt QSyntaxHighlighter](https://doc.qt.io/qt-6/qsyntaxhighlighter.html)

## 4. 双向导航规则

T2.0 的 `SclWorkspace::Select` 负责同步树和详情。T2.1 增加中央页签和行定位，保留不同用户入口的行为差异。

| 用户入口 | 工作台响应 |
| --- | --- |
| 树选 IED、LD、LN 等结构节点 | 切到节点概览，展示当前节点的可进入分类及作用域。详情跟随。 |
| 树选报告、数据集、FCDA、对象、通信或模板 | 按目标类型切到对应表并选中可见行。FCDA 先建立所属数据集的成员范围；无对应表行的节点使用节点概览。 |
| 表格选行、搜索结果、引用跳转 | 展开树的祖先并滚动到目标。表格选行保留当前页签；搜索与引用激活按目标类型路由。保留属性、引用或原文页的阅读偏好。 |
| 问题激活 | 保留问题上下文，明确打开诊断位置的原文；可定位节点时同步树。 |
| 目标被筛选隐藏 | 树和详情仍定位，表格清除旧行高亮并提示「目标被当前筛选隐藏」，提供显式清除操作。 |

每次用户导航只记录一次。用信号阻断或有限作用域重入保护避免树与表回调循环。历史以快照内节点、表类型、成员范围及详情页为基准，恢复时按当前模型查找可见行，避免把代理模型行号当作稳定身份。文档切换后清空旧历史并拒绝旧搜索批次；加载失败时仍可返回已打开文档。通过浏览索引和模型行映射定位，避免在 GUI 线程扫描整棵树或全表。

## 5. 交互式引用拓扑（本轮必交）

入口放在「引用」页，并在报告、数据集、FCDA 和支持的对象行提供同一操作。以当前项为中心打开局部图，标题显示焦点、文件名及快照摘要。图用于解释 SCL 中的配置关系。每种连线标出关系及方向，图例与详情区用文字区分包含、引用、候选与派生。

| 视图 | 展示与交互 |
| --- | --- |
| 对象引用来源 | 左列列出 FCDA 原始字段，中列显示匹配的 IED / LD / LN 及 DO / SDO / DA / BDA 定义，右列显示对象引用和可用的派生 MMS 映射。点 `ldInst`、LN 相关字段、`doName`、`daName`、`fc` 或 `ix`，高亮对应证据，详情显示字段原值、解析状态、来源节点和行号。按实际解析结果区分显式声明、缺省作用域、模板定义和推导。 |
| 数据集与 FCDA | 显示「报告定义 → 引用的数据集 → 按原顺序排列的 FCDA → 解析目标」。成员保留各自序号和声明；同数据集成员通过共同父节点呈现。反向视图展示已解析到同一对象的成员和相关数据集，按逻辑节点实例及对象路径识别目标，结合 FC、数组索引及组件区分访问。共享模板定义单独标示，跨 LN 复用同一模板时仍显示各自的实例。 |
| 解析失败或不完整 | 从声明连到带文字的状态节点。歧义分支列出候选，选中候选只查看证据。缺失、部分解析、受限与外部引用保留原值和已知的最后一步，目标未知时在该步终止。 |

支持缩放、平移、适配视图、点击节点或边查看详情、聚焦关联路径、展开或收起邻接分组，以及键盘可操作的等价关系列表。详情提供已采集位置的同快照原文片段，并可复制完整引用和文件名、快照摘要、行号。首版浏览器与主程序独立选择，回到主窗口可用已有搜索或文件位置对照。初始画布暂按最多 80 个可见节点设计，超出按数据集、关系类型及成员序号分组分页，显示剩余数量。浏览器内按已装载的局部数据展开，超出本次装载范围时提示回主程序从目标重新打开。

### 技术路线

- **Qt 负责取证。** 应用服务在后台用当前不可变快照生成有界的局部图和原文片段。复用 `ReferenceAnalysis` 的 `incoming`、`outgoing`、候选、所属 LN、FCDA 序号和报告映射。现有结果提供终点及部分上下文。对缺少的逐段证据，在现有 C++ 解析路径按需记录匹配节点、字段和停止原因，并验证同现有结果一致。浏览器消费带版本的图数据，字段包含节点与边类型、关系状态、证据、来源位置和快照摘要。
- **浏览器负责呈现。** 首选主程序生成并打开本地独立 HTML，用原生 JavaScript、内联 SVG 和分列布局实现交互。页面资源随 CMake 构建分发，全部离线，首版采用单文件输出，避免依赖本地 Web 服务、CDN、WebView 或 QML。浏览器启动失败时提示重试和可用的本地打开入口。 [SVG in HTML](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/SVG_in_HTML)
- **控制本地数据生命周期。** 仅写入本次图所需的数据与有限原文，不嵌入整份 SCD 或绝对工程路径。应用专用临时目录中的页面以只读快照标注，提醒切换或重载文档后需重新打开。退出时尽力清理，启动时清理上次遗留，浏览器已打开页面仍可能保留已载入的内容。将工程文本作为数据做安全编码并用文本节点渲染，验收覆盖脚本闭合标签、引号及扩展字段。

## 6. Qt Widgets 与 QML

本轮继续使用 Qt Widgets + ADS。QML 做自定义视觉组件、状态和过渡通常更方便；这次工作量主要来自双向导航、筛选映射、快照一致性和高亮边界，这些工作在 QML 中仍要实现。Widgets 可直接复用已有 Item Model、选择模型、树表和原文文档，通过局部调色、delegate 和小型路径控件完成改造。

本轮引用拓扑采用独立浏览器视图。若将来要让图与桌面树实时互选，再评估 Dock 内嵌路线，复用应用服务提供的局部图数据。
