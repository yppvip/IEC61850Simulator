## 1. 需求判断与推荐决策

需求足以开展产品设计：希望以 IED 为中心，快速找到四遥信号、GOOSE 和 SV，理解它们的关系，并能回到原文核对。当前的困难是用户必须先理解报告、数据集、模板等技术分类，才知道去哪个 Tab 查找。建议将默认入口改为“找信号、看收发、查问题”，技术结构保留为高级视图。

本期定位为“可解释的离线工程查阅工具”。打开文件后回答四个问题：这个 IED 有什么信号；信号通过什么配置使用；哪些 IED 声明接收它；结论来自文件哪里。支持 CID/SCD/ICD，CCD 延续既有方言识别限制；不因扩展名匹配就承诺支持其语义。

以下概念需要澄清，但不阻止先执行 T4.0：

| 用户表述或约束 | 边界与建议默认值 |
| --- | --- |
| 每个 IED 的“四遥” | 遥信、遥测、遥控、遥调是业务分类，不能仅由数据集名称或 FC 自动完整确定。默认给出可追溯的规则建议，保留未分类和冲突项；不宣称生成了完整调度点表 |
| MMS 报文 ID | 不是一个唯一明确的 SCL 字段。分别展示对象引用、MMS Domain/Item、RCB 定义引用和原始 rptID；若用户指抓包 invokeID 或业务点号，属于另一需求 |
| 校验是否有内容缺失 | 可以检查明确覆盖的结构与引用缺失。缺少现场应有的某个信号，需要经确认的点表/工程规范作比较基准；单份 SCL 无法证明工程完整 |
| GOOSE/SV 信息 | 本期展示配置、成员顺序及有证据的接收关系；实时帧、在线通道值、丢包、波形、实际报告实例和在线可控性需后续通信能力 |
| 外观、动效参考 | 保留 Widgets + ADS，借鉴 finesse 的信息层级、留白、色彩及反馈；GSAP 是 Web 动效参考，不直接作为 Qt Widgets 依赖 |
| 库与独立程序路径 | 库源码仍在 `D:/Code/IEC61850Simulator/third_party/`；用户本轮指定独立程序由 `E:/Code/IEC61850Simulator/tools/` 管理。该 E 盘目录本次检查不可访问；本期不需要新增独立程序，不创建目录、不迁移现有 Redis、不改运行配置 |

可选补充信息按价值排序：① 是否有四遥点表或厂家分类规则；② “MMS 报文 ID”所指字段的一个脱敏示例；③ 优先用于培训查阅还是工程核对、常用屏幕/DPI。默认先服务初学者查阅，保留技术字段；没有额外资料也可以开发，但相应结论必须标明证据边界。

## 3. 给初学者的概念模型

| 概念 | 用户看到的解释 | 需要避免的误解 |
| --- | --- | --- |
| IED | 一台装置的模型和配置容器 | 名称相同不代表身份一定唯一，还要保留 AP/Server 范围 |
| LD / LN | 装置内的逻辑设备 / 功能节点 | 不要求用户先背缩写再找信号 |
| DO / DA | 业务对象 / 对象的具体属性，例如位置对象及其状态、品质、时间 | q、t 等是附属属性，不各算一个遥信 |
| 类型模板 | 说明对象具有什么结构 | 没有 DOI/DAI 不等于信号缺失；实例可由 LN 的类型声明导出 |
| 数据集 / FCDA | 一组有顺序的成员 / 一个成员声明 | 数据集不等于四遥分类，也不等于通信帧；同信号可多次使用 |
| 报告控制块 | 配置通过 MMS 报告哪些数据及触发方式 | rptID、RCB 引用、MMS Item 是不同字段；定义不等于已运行实例 |
| GOOSE / SV | 事件类信息传递 / 采样值传递的配置 | 业务分类与通信方式是两条轴；同一对象可出现在不同服务中 |
| ExtRef | 接收端声明的外部信号引用 | 当前文件未声明接收方不等于没有实际接收方 |

在字段旁提供短释义，例如“FC：此属性的功能分组”；全称、枚举解释与高级细节按需展开，不依赖悬停才能获取关键信息。

## 4. 信息架构与主要操作

### 4.1 默认布局

沿用工作台内部独立 ADS 管理器；重组 Dock 内容，不再增加一批平级业务 Tab。

```text
打开 / 重载 / 校验摘要    全工程搜索 [信号、描述、引用、ID]    文件与覆盖状态
┌────────────────┬───────────────────────────────────────────────────────┐
│ IED 搜索与列表  │ 当前范围：IED A（可回整个工程）   后退 / 前进 / 高级视图 │
│ 名称 + 描述    │ 概览 · 信号查阅 · GOOSE · SV · 文件检查               │
│ 当前装置标识   │ 本页条件：分类 / 方向 / LD / 服务 / 解析状态           │
│                │ 结果数量与统计口径 → 按需表格                         │
├────────────────┼───────────────────────────────────────────────────────┤
│ 可折叠结构树   │ 已选对象：是什么 → 如何使用 → 谁声明接收 → 文件依据    │
│ 高级入口       │ 属性与来源 / 局部关联链 / 周围 XML（按需打开）        │
└────────────────┴───────────────────────────────────────────────────────┘
```

上方五项是稳定的任务导航，中央用 `QStackedWidget` 等呈现当前任务；不再要求横向切换十余张技术表。空业务保持可发现入口并解释“当前文件/范围未声明”，筛选零命中提供清除条件。原有高级表格的无内容 Tab 隐藏规则仍只作用于高级视图，不与任务导航混用。

IED 列表默认显示名称和描述，支持本地筛选；全工程保留无法归属、歧义及站外来源入口。顶部范围标识一直可见，切 IED 不随表格某一行被动改变；只有显式跨 IED 跳转改变范围并记录历史。

“概览”是行动入口：查看信号、查看 GOOSE/SV、检查问题。显示带口径的计数和覆盖提示，不用大面积统计卡片挤占结果表。

### 4.2 信号查阅

默认显示当前 IED 自身的对象实例；“外部输入”是独立方向筛选，不把接收声明重复算作本机信号。分类入口为遥信、遥测、遥控、遥调、其他/未分类，默认可查看全部。状态/控制兼具的对象允许拥有多个能力标签，但总数按信号身份去重。

默认列：业务名称、建议类别、对象路径、数据类型/CDC、使用服务、解析/分类状态。技术列按需增加 FC、MMS Domain、MMS Item、所属 LD/LN。业务名称分别标注实例描述 dU、实例 desc、模板 desc 的来源；没有描述时显示技术名，不编造中文名称，冲突的描述可展开对照。

点击行即可在下方显示：

1. **这是什么**：中文释义、原始描述、技术路径、分类依据、是否配置型值。
2. **如何使用**：所属数据集及原始成员序号，关联的报告/GOOSE/SV；一对多显示数量并允许展开。
3. **谁声明接收**：接收 IED、LN、ExtRef 和匹配证据；区分唯一、歧义、部分、站外和未声明。
4. **文件依据**：实例声明、类型定义、FCDA、控制块和通信节点分别可定位原文，预览跟随当前快照。

默认一行是一个有业务意义的 DO/SDO 实例对象，复合测量对象可展开子量，再展开 DA。品质 q、时间 t 和单位是附属属性。DO 级 FCDA 保留为对象级使用，未展开前不假装对应某一个 DA。提供“对象数 / 已展开属性数 / 成员出现次数”独立口径，不用同一个“点数”混算。

### 4.3 GOOSE 与 SV

先按“发送配置 / 接收声明”分组，每条控制块配置可展开成员。多 AP、网络冗余和多通信地址作为同控制块的多个端点显示，不能按名称简单合并，也不重复统计成多个信号。

| 页面 | 默认摘要 | 展开内容 |
| --- | --- | --- |
| GOOSE | 发送 IED/AP、控制块、原始 appID、数据集、成员数、MAC、APPID、VLAN、绑定状态 | confRev、地址来源、MinTime/MaxTime、每个 FCDA 的原始顺序/引用/解析状态、接收证据 |
| SV | 发送 IED/AP、控制块、原始 smvID、数据集、成员数、采样声明、MAC/APPID/VLAN | smpRate、smpMod、nofASDU、SmvOpts、各成员顺序/类型/单位及其来源、接收证据 |

GOOSE 的 `GSEControl@appID` 与 `Address/P[type=APPID]` 分列；前者不作为链路层数值 APPID，映射到报文 goID 的解释须核对支持版本。SV 的 `SampledValueControl@smvID` 与数值 APPID 分列。原文字符串和规范化显示分开，解析失败保留原值。

采样率只有在版本、smpMod 和必要频率依据已确定时才转换为 Hz；缺失单位标记“未声明/无法推导”。不固定假设 50 Hz、80 点/周波、固定通道数或直接给出报文字节偏移。数组和复合成员展开有预算；保留结构及成员次序，不把任意 FCDA 顺序直接称为已验证的实际报文布局。

接收关系优先采用唯一解析的 ExtRef 控制块和数据引用。缺少 serviceType 时，可按已声明的源控制块字段在合法作用域内查找各服务候选；仅一个候选且其他证据一致时标为“依据控制块推导”，多个候选列出歧义。仅数据对象唯一匹配时，只证明对象关联，不能确定某一发布流。仅同名、MAC 相同或模板相同不建立接收边。

### 4.4 报告与 MMS 的查看路径

初学者从信号的“如何使用 → MMS 报告”进入；专业用户从高级视图直接看报告表。

按三个分组呈现：原始声明（name、rptID、datSet、buffered、confRev、RptEnabled 等）、静态派生引用（数据集引用、RCB 定义引用、MMS Domain/Item）、运行时信息（本期未采集）。索引实例、默认 rptID 以及客户端分配不可无证据生成。样例路径和 `$` 分隔形式仅表示受支持规则下的静态映射，不承诺与所有设备运行时一致。

### 4.5 搜索与导航

顶部为“全工程搜索”，结果明确显示 IED、对象类别、匹配字段、路径和解析状态。当前任务内另有“筛选当前 IED/页面”，不暗中切换范围。首版支持描述、对象路径、引用、rptID、GOOSE appID、smvID、数值 APPID 和 MAC；技术 ID 精确匹配优先，中文描述支持子串；分词/别名是独立可解释匹配，不引入在线服务。

搜索结果、问题和关系链使用统一导航目标：快照身份、IED/AP/Server、任务页、对象实例键、来源 NodeId、成员原始序号及问题原始序号。跨范围前清楚显示目标 IED；跳转后能后退回原范围、筛选、选中和滚动位置。筛选挡住目标时保留目标说明，提供“清除筛选并定位”，不能高亮旧行。

常用操作支持键盘：Ctrl+F 聚焦搜索、方向键选行、Enter 打开关联目标、Alt+左右恢复历史、Esc 退出当前临时展开；最终快捷键在 T4.3 核对现有绑定。不能要求双击或悬停才能查看关键信息。

## 5. 四遥分类方案与不确定性

分类属于业务解释层，不能修改原始 SCL。规则带版本、适用范围、条件、证据与测试；规则更新后可重建索引。不得为了凑四类而强制归类全部对象。

| 类别 | 建议依据（待 T4.0 固定首批规则） | 排除与注意 |
| --- | --- | --- |
| 遥信候选 | SPS、DPS、INS 等状态对象及实际 ST 属性，结合 LN/DO 语义 | ST 包含广泛状态信息，不全是调度遥信；品质、时间不单独计点 |
| 遥测候选 | MV、CMV、WYE、DEL 等测量结构及 MX 属性；复合量按层次展示 | WYE/DEL 不整块重复计数其所有子量；SV 中的采样值保持采样语义 |
| 遥控候选 | SPC、DPC 等控制对象，结合 CO 路径和 ctlModel 声明 | 同对象的 stVal 是反馈；不能因整数/布尔类型就认定遥控，也不保证可在线执行 |
| 遥调候选 | 可调模拟/整数量的控制语义及明确工程规则 | SP、SG、SE 不直接全归遥调；定值/配置参数默认单列。APC、INC 等需结合语义核验 |
| 其他/未分类 | 设备标识、描述、定值、配置、厂家扩展、证据不足或冲突 | 可检索、可解释、可查看原文，不从页面隐藏 |

类别与依据状态分开：规则建议、工程规则确认、未分类/冲突；引用解析状态另列，不用百分比伪装可信度。没有点表时只有规则建议，不输出“工程确认”。人工覆盖/点表导入是后续可选功能，若实施须单独保存绑定快照或对象键的规则，不能偷偷回写 SCL。

需要从 LN 类型展开实例能力目录，而非仅扫描 FCDA 或 DOI/DAI。不在任何数据集中的控制对象仍可进入目录；未解析类型的 LN 保留一条覆盖不足记录，不能显示为“0 信号”。模板复用必须按 LN 实例区分；相同模板不同实例是不同信号，同信号在多个数据集中的使用记录是多个出现位置。

## 6. 文件检查与原文证据

检查中心分层显示，层级分别计状态，不用一个绿色勾代表“文件完整”：

1. 文件与 XML：读取、编码、XML 良构、安全与资源上限。
2. 内部一致性：已实现的标识、类型、作用域、数据集、FCDA、通信和 ExtRef 子集。
3. 工程提示：预留数据集、疑似冲突、未使用定义等，按已实现规则展示；未实现项目列明。
4. 完整 XSD：由原 Task1 P7 独立实现，未交付前明确“未执行”。即使 XSD 通过，也不证明现场点表完整。
5. 工程点表完整性：需要外部基准，本期不执行。

每条问题解释“发现了什么、影响哪些对象、如何核对”，按根因组织并显示受影响数量，保留原始问题序号及规则版本。零问题、规则未执行、检查受阻和当前筛选零结果有不同空态。

点击“文件依据”预览当前快照中节点前后有限行数，延续现有编码/位置映射和词法边界。多个证据分别列入口；不把模板位置冒充实例位置。失败文件原文使用失败快照，不能套用当前有效文档的 NodeId。外部磁盘变更只提示重载，不能让显示内容与诊断来源漂移。

## 7. 技术实现方案

### 7.1 数据管线与边界

```text
原始字节快照 → Reader / ReferenceResolver
             → 现有 BrowseIndex + 新增业务查阅索引（后台、有预算）
             → 完整不可变分析快照 → ViewModel / ItemModel → Widgets + ADS
```

建议新增职责（文件名为方案，T4.1 后按现有项目风格落实）：

| 层 | 建议模块 | 职责 |
| --- | --- | --- |
| 领域层，仅 Qt Core | `src/iec61850/scl/SclSignalCatalog.*` | LN 实例/类型路径展开、信号身份、附属属性、解析证据 |
| 领域层，仅 Qt Core | `SclSignalClassification.*` | 有版本的分类规则；输出类别、依据、限制 |
| 应用服务 | `src/core/SclSignalBrowseIndex.*` | IED/方向/业务页行映射、按身份反查使用位置、搜索字段索引 |
| 应用服务 | `SclCommunicationCatalog.*` | 发布流、通信端点、接收声明及证据投影，复用已有解析结果 |
| GUI | 对应 ViewModel、ItemModel 和工作台任务页 | 按需显示、导航与状态管理；不在 `data()`、点击槽或绘制中解析类型/全量扫描 |

信号键至少包括快照、所属 AP/Server、LN 实例、DO/SDO 模板路径及数组索引；属性键再含 DA/BDA 路径和 FC。数据集使用键含 DataSet NodeId + FCDA 原始序号。控制块/端点保留节点身份和合法作用域，不能只按显示字符串去重。导航键必须支持“实例 + 模板证据”，单个模板 NodeId 不足以表示信号。

关联图复用既有局部拓扑：信号 → 成员出现位置 → 数据集 → 报告/GOOSE/SV → 通信端点 → 接收声明。模板复用边独立显示，不冒充同对象使用。图有节点/边/层数上限及“还有 N 项”入口，逐段按需展开；默认详情使用可点击关系列表，拓扑是辅助理解入口。

### 7.2 大文件和异步契约

类型共享结构，实例目录使用紧凑路径/引用；不复制整棵模板树为每个实例创建 Widget 或长字符串。大数组和深层结构按需后台展开，保留未展开数量/范围和覆盖状态；为节点、数组元素、关系和内存设置可测试预算。超过预算返回“受限”，不静默丢掉结果后宣称完整。

首次业务索引在后台构建，完整交付当前版本索引；后续按需展开使用独立取消标记。每份结果都校验快照、请求代次、IED/任务/成员范围；切换、取消、重载、失败和关闭均不能让旧结果回填。保留当前单文档会话及失败不替换有效快照的约定。GUI 不等待工作线程，不使用 `processEvents()` 掩盖长工作。

搜索与筛选复用独立会话，批次条数、GUI 时间和队列容量均有上限；计数注明是否完成、是否受限。新增索引可以提升查询成本，但须测量加载和内存，不把性能预算留到最后。

## 8. 外观、图标和动效

设计方向：明亮、克制的工程查阅工具。冷灰底、深色正文、单一青蓝强调色；分类以文字和小图标表达，红黄仅用于问题严重度。保留原生树表高效绘制与清楚的选中/键盘焦点。没有照片、AI 位图或装饰性背景需求。

建议初始设计令牌：底色 `#F6F7F9`、主文字 `#202A35`、次文字 `#526170`、强调 `#176E83`；这些是原型候选值，须在真实 Qt 渲染中检查文本对比度、禁用态和高对比模式。使用系统中文字体；技术路径和 ID 可用本机等宽字体，不下载网络字体。表格行高约 28–32 逻辑像素，长路径省略但可复制完整值；不靠超大卡片撑布局。

本方案借鉴已全局可用的 finesse-ui 产品界面原则。两项需要原型验证的取舍是“解释内容会不会占用过多表格空间”以及“简化入口后专业字段是否仍容易到达”；以可折叠说明和高级视图解决，并纳入可用性测试。本轮没有页面构建，不生成素材、不修改技能，也不建立设计构建日志。

图标优先一套本地 SVG 或自制矢量，统一线宽/尺寸，采用 IED、信号、输入/输出、报告、网络、问题、原文等可辨语义。Yesicon/Ahaicon/IconMCP 仅作候选来源；正式选型时核对每个图标集的许可证、来源、版本/提交及署名要求，不把聚合站当成统一授权。资源嵌入 qrc，新增依赖记录进入 `third_party/DEPENDENCIES.md`，离线运行不请求图标服务。

动效仅服务反馈：展开/收起约 120–160 ms、定位背景提示约 200 ms，可关闭；滚动跟随、数据加载和批量重置不播放逐行动画。Qt 侧优先原生行为与 `QPropertyAnimation`，不动画全表高度、不为动效增加 QML/WebView。已有离线 HTML 图若确有需求，可另评估原生 Web 过渡；本期不引入 GSAP 运行库。系统减少动效/应用关闭动效时直接到终态，导航与可访问性一致。

## 12. T4.6：双向虚端子关系查阅（2026-11-13）

### 12.1 从举例归纳的产品需求

这项需求属于**离线虚端子关系查阅与追踪**：既需要装置级的“谁发给谁”，也需要成员级的“发送哪个对象、数据集第几项、接到哪个内部地址”。本轮只读绘制与查阅，不编辑虚端子接线、不回写工程、不模拟设备。

每个 IED 必须具有对称的两个入口：

- **接收自**：上游 IED → GOOSE/SV 发布流 → 网络参数 → 原始成员 → 当前 IED 的 ExtRef/intAddr。
- **发送到**：当前 IED → 发布流及全部成员 → 文件中声明的接收 IED/内部地址。未见接收方时仍展示发布流与所有成员，不能显示为空或声称没有发送。

从 ML2201B、IL2201B、PL2201B 推广得到的操作要求：按 IED 定范围；按 GOOSE/SV 切服务；按对端、控制块、APPID、MAC 搜索；关系树选择一条流后同时看到通信标识和成员映射；支持从任一端进入同一关系，随后查原文和后退。源属性缺省和重复使用必须可解释，不能因关系复杂就取第一个候选。

### 12.2 技术选择：Widgets 外壳 + Graphics View 局部图

Qt Widgets 并不局限于表单。Qt 的 [Graphics View Framework](https://doc.qt.io/qt-6/graphicsview.html) 提供场景、图元、交互及视图变换，能够在现有 ADS 工作台内呈现节点关系图。当前缺口首先是关联索引及信息架构，而非框架本身。

本轮采用 `QTreeWidget` 的有界关系树、分页 `QTableWidget`、面包屑、详情与 `QGraphicsView/QGraphicsScene`。图只画当前成员的局部链，支持平移、缩放、成员切换和节点原文跳转；不绘制全站几万根交叉线。Qt Core/应用服务在后台提供同快照关系证据，GUI 不重新解析 XML。

若后续需要大规模自由布线、自动布局、拖拽编辑和跨视图连线，可在保持同一数据契约的前提下单列 QML 或本地前端画布原型。本次没有新增 QML、WebView、JS 运行库或在线服务依赖，原有离线 HTML 引用拓扑仍可从高级视图使用。

### 12.3 页面与交互

新增稳定顶层入口「收发关系」，任务区右上始终提供「查看双向收发与成员映射」。从 GOOSE/SV 页点击该按钮会带入对应服务；当前 IED 范围沿用整个工作台。

```text
当前 IED                         [查看双向收发与成员映射 →]
概览 / 信号 / GOOSE / SV / 检查 / 收发关系
[全部服务 / GOOSE / SV] [发端、收端、控制块、APPID、MAC 搜索]
范围统计：IED、发布流、接收 IED、明确映射、候选映射、未定位输入
┌─────────────────┬────────────────────────────────────────┐
│ ↑ 发送到        │ 工程 / 发送 IED → 接收 IED（可点击）     │
│   对端 IED      │ 控制块、appID/smvID、APPID、MAC、VLAN     │
│     服务 / 流   │ 明确/候选数量与证据说明                  │
│ ↓ 接收自        │ 成员映射 | 关系图 | 成员详情             │
│   来源 IED      │ 原始序号 → 发送成员 → 接收 intAddr       │
│     服务 / 流   │ [发送成员原文] [接收原文] [配置依据]     │
└─────────────────┴────────────────────────────────────────┘
```

成员映射默认保留完整数据集，缺少接收声明的成员有明确文字。勾选「仅看有映射的成员」聚焦当前对端实际声明的信号；保留重复 FCDA 序号，同成员接入多个内部地址显示多行，不合并丢失信息。每页最多 200 行，上一页/下一页清楚显示当前范围和总行数。Ctrl+C 可复制选中行。

关系图画“发端成员 → 发布流/APPID → 收端内部地址”。发送成员属于发布流的解析证据用实线；控制块绑定用实线；仅由成员匹配得出的收端关联用虚线，文字同步说明候选。用户可以在图上方直接切换当前页成员，拖动平移、Ctrl+滚轮或按钮缩放、适应窗口、双击有证据的节点定位原文。成员详情保留完整文本，长技术路径和地址可复制。

服务色：SV 使用青蓝，GOOSE 使用紫色；方向用箭头，装置和发布流用不同原生图标，候选增加问号标记及文字，不单靠颜色判断。图使用系统调色板，深色/高对比时使用可读文字/线色；无新增图标许可依赖。关系树可收起，长表横纵滚动，通信摘要有独立滚动区域。图隐藏时不固定使用隐藏控件的尺寸缩放，显示/缩放窗口后自动适配。

### 12.4 数据与证据规则

原实现仅在有源控制块字段且匹配成员时设置 `matchedStream`。新样本中的输入没有这些字段，因此对象已解析仍无法在 GOOSE/SV 接收页表达关系。修订增加独立 `MemberLink`，**不把成员候选写成 `matchedStream`**。

1. 复用唯一解析的 ExtRef 源 LN 实例、对象路径和已解析 FCDA；实例、AP/Server、DA、FC、数组语境保留。模板相同、名称相似、内部地址前缀或 MAC 相同均不能作为建立关系的依据。
2. 明确控制块绑定继续使用已有结果；缺省控制块字段时，按实际发布数据集的成员建立候选，列出所有适用 GOOSE/SV 流。多个控制块保留多个候选，不选首项。
3. DO 级与 DA 级包含关系单列为“对象包含候选”。DA 已知的 FC 必须与 DO 级 FCDA 的 FC 一致；未知数组选择不建立映射。显式但无效/矛盾的源控制块不能退化成猜测其他流。
4. 声明 serviceType 时约束候选服务；未声明时按发布控制块类别分到候选服务页，原始 serviceType 字段仍保持空。候选可以同时出现在两个服务中，不能称为确认订阅。
5. 原始 GOOSE appID、SV smvID 与数值 APPID 独立显示。多个网络端点逐一保留 AP、APPID、MAC、VLAN，不随意合并或把第一个地址当作唯一地址。
6. “未见接收声明”只表示当前文件证据不足；不推断没有现场接收方。厂家 Private 未识别语义不作为标准连线证据。

`SclTaskIndex` 在后台构建成员映射、按控制块/输入的反向索引及去重候选控制块列表。关系构建比较/条目预算为 250,000，关系树查询最多交付 512 个关系条目；受限时显示提示并支持缩小范围。后台查询和成员页分别使用独立取消标记，结果须匹配快照与请求身份；范围、服务、过滤、关闭与旧结果的交叉交付不得污染当前界面。历史恢复关系身份、过滤、服务、成员页与当前行；不持久化跨文档 NodeId。该版本不改变 ADS 静态 Dock 结构，内部布局版本继续为 2。
