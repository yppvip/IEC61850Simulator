## 2. 对“大量数据绑定 UI”和“通过 UI 元素跳转”的回答

现状不是为全部 XML 元素创建 Widget/Item。`SclWorkspace.cpp` 的 `SclTreeModel`、`SclTableModel` 继承 Qt 抽象模型，共享不可变快照，视图按需读取。`SclBrowseIndex.cpp` 提前建立父子行、分类和数据集成员索引。全量领域数据存在内存中不等于全量生成界面控件，也不意味着每次重绘都扫描全文件。

当前跳转链为：后台搜索结果中的 NodeId/问题原始序号 → `Select` → `ForNode` 创建树索引 → `RowForNode` 在文档顺序分类表中二分定位 → `VisibleRow` 映射到筛选后行 → 设置选择与滚动。没有发现通过遍历所有 UI 元素进行全局检索的实现。引用跳转也使用快照身份；`QModelIndex` 仅作为显示适配，不应成为领域身份。

但“使用 Model/View + 后台解析”不足以保证不卡顿。选择回调、模型重置、字符串格式化、富文本排版、关系集合构造和批次交付仍可占用 GUI 线程。应定位一次交互同步执行了多少工作，而不是直接归因于绑定或换用 QML。

## 3. 源码证据及待验证热点

以下是静态审查结果和风险，不是已确认的卡死根因。代码位置以函数名为准。

| 路径 | 已观察到的行为 | 风险与验证方式 |
| --- | --- | --- |
| `SclWorkspace::Select / UpdateDetails` | 节点变化时同步更新路径、概览、属性 HTML、引用模型、候选模型；原文已有可见时才生成的机制 | 即使属性/引用页未显示，仍生成其内容；分别计时生成、`setHtml`、重置与布局，比较隐藏/展开详情 |
| `SclTableModel::Reset` 的 Links 分支 | 获取当前节点全部 incoming/outgoing，构造集合并排序 | 共享模板等高入度节点可能明显慢于普通报告；测引用数量与耗时，避免把 O(k log k) 操作留在每次点击中 |
| `SclTableModel::Cells / data` | 有最近一行缓存；读取路径、属性、引用计数并格式化，成员表包含实例 `dU` | 缓存只覆盖最近一行；部分字段长度没有展示上限。统计绘制期间 data 调用次数、最大单元格长度及单次耗时，不能仅统计行数 |
| `UpdateDetails` | 原始属性和节点文本已有部分截断，但 FCDA 派生字段、实例描述等不统一受同一总量限制 | 超长工程字段可能放大 HTML 转义及排版；构造长字段样本，不先假定所有 HTML 都无界 |
| `SclWorkspaceSearch.cpp` 的 `currentChanged / ScheduleSearch / ResetSearch` | 当前表格筛选模式切页时取消旧请求、清结果、恢复旧表过滤，再延迟启动新查询 | GUI 重置及重新布局可能先于后台筛选造成停顿；记录单次切页的信号、reset、查询代次和绘制次数 |
| `SclSearchSession::Drain` | 每 35 ms 取走当前积累的全部 hits，同步发出 BatchReady；生产侧在锁内追加 | 定时不等于每次处理有上限；大匹配量可能导致 GUI 批次过大或锁等待，需测队列长度及锁耗时 |
| 树 `scrollTo`、表 `LocateTableRow` | 使用模型索引滚动和选择，已有 `m_restoring` 重入保护 | 测深层未展开节点、高扇出树布局以及回调次数；已有保护不等于所有路径都已证明无重复刷新 |

`UpdateOverview` 当前使用祖先链与分类二分统计，不是整棵树扫描；表格已有固定行高，不能把这些已存在的设计当作新优化成果。引用拓扑本身已有后台生成机制，只有证据指向其导航附带工作时才纳入本次修改。

## 5. 优化目标与设计

### 5.1 选择只做必要工作

保留现有索引和快照模型。选择入口先完成身份校验、轻量选中反馈和路由；属性、引用、原文分别维护 dirty 状态，仅在可见且目标变化时刷新。不能因为详情延后而延后数据集成员作用域设置；应先将作用域从 `UpdateDetails` 中解耦，保证 FCDA 路由和筛选正确。

一次用户操作只形成一次导航事务与历史记录。树表反馈使用限定作用域的重入保护；重复选择相同节点且上下文无变化时不重复 reset。连续方向键浏览可合并未执行的重详情请求，仅保留最后一个目标，但选中反馈不等待，显式问题激活与历史顺序不得丢失。禁止用循环调用 `processEvents()` 掩盖长操作。

### 5.2 高入度关系和大批次有界处理

若证实 Links 构造为热点，优先在后台索引阶段建立有序邻接索引/范围，GUI 引用模型按需读行；避免为全部节点复制关系对象。若索引内存代价过高，改为应用服务按目标异步构建并使用有容量上限的缓存。引用顺序、方向和歧义候选保持现有语义。

搜索采用有上限的交付批次和队列容量；GUI 单轮处理达到时间预算后让出事件循环。生产侧背压必须可取消，GUI 不等待工作线程。已取消或过期批次按快照、查询代次、表类型与成员范围拒绝；最后一批未交付前不能提前标记完成。显示更多只控制可见行数，不可被误认为限制了后台结果内存。

### 5.3 展示格式有预算

模型 `data()` 不做文件读取、搜索、解析或大集合排序。给长字段展示、tooltip 和详情 HTML 设置统一长度/总量预算，截断明确可见；完整字段仍保留在领域快照，并提供显式查看或复制原值入口。XML 保留有限窗口及同快照词法定位。

仅在测量证明必要时将一行缓存扩展为按快照、表类型、作用域和原始行标识索引的有限 LRU，记录容量与内存，避免预格式化所有行。格式变化和快照切换必须失效。大表保留固定行高，不引入全表自动内容测宽；树布局若成为热点，再验证一致行高和展开范围策略。

### 5.4 异步边界

任何新增工作线程只消费不可变快照及独立取消标记，不持有或修改 Widget、QAbstractItemModel、QTextDocument。结果经 GUI 线程应用，并核验快照及请求代次。关闭、重载、失败、快速切换均不允许旧结果覆盖当前选择；不在 GUI 析构路径等待未结束任务。性能优化不得改变缺失、歧义、模板复用和实例 `dU` 的解析含义。

### 测试矩阵与拟定指标

- 节点：IED、LD、LN、报告、数据集、FCDA、DOI/DAI、最大入度模板、歧义引用、问题、深层未展开节点。
- 页签：全部中央表格的首次进入与重复进入；属性/引用/原文可见及详情收起；当前表格筛选中快速切页；搜索大量命中、取消、重载、关闭和历史恢复。
- 自建样本：按 1×/2×/4× 扩大节点与引用数量，额外独立构造高扇出、高入度、超长字段及多诊断样本；不要只复制普通报告。性能测试显式运行，常规 CTest 以正确性和处理上限断言为主，避免机器计时抖动造成随机失败。
- 每类交互至少 100 个样本，分开记录首次和热态的 P50/P95/P99/最大值；端到端包含事件处理和目标视图完成绘制，另记 GUI 槽与后台任务耗时。实体桌面与 offscreen 不混为同一口径。
- 拟定目标：选择/切页到可见反馈 P95 ≤100 ms、P99 ≤200 ms；GUI 心跳最大额外延迟 ≤200 ms，无超过 1 s 的无响应。单次 GUI 批次目标 ≤8 ms，超时拆分。若详情需异步超过 100 ms，显示明确加载状态，仍可继续导航；有界局部详情目标 P95 ≤500 ms。
- 同机同构建加载中位数和峰值工作集相对 T3.0 增量原则上 ≤10%；索引换时空若超过预算，必须记录收益、容量和取舍，不能默认为通过。十轮关闭后快照应释放，内存不随轮次持续增长。
- 卡死时采集多次线程栈及 CPU 采样，区分 GUI 计算/排版、锁等待、后台竞争或事件循环重入；全程低 CPU 也不能直接断言死锁。正常日志只记录阶段、耗时、计数和匿名身份；可能包含工程原文的转储留在本地。
